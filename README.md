## 0. 一句話目標

把一趟日本旅行的照片與短片，做成**像博物館展覽牆一樣的年代表網站**，用 Astro 建置，方便之後逐日補上內容並長期管理。

### 快速開始

```sh
npm install                 # 需要 Node ≥ 22.12
brew install ffmpeg         # 匯入短片用；只看網站可以不裝
npm run dev                 # http://localhost:4321
```

新增一天：把原始檔放進 `raw/<日期>/`，在 Claude Code 執行 `/add-day <日期> <城市>`。

### 參考照片的內容（使用者提供的實體展覽牆）

台灣某展覽（漢聲雜誌相關）的年代牆，特徵如下，網站版需要保留這些「語彙」：

- 大號年代數字（1970、1980、1990、2000、2010），**基準橫線由左往右逐段升高**，轉折處有直線連接。

- 刻度下方是**密排的文字欄**，穿插大小不一的圖片（書封、人像、剪報）。
- 牆前方垂掛**紅色直式標題布條**（「漢聲雜誌」）與一幅彩色版畫布條。
- 天花板有軌道投射燈，在牆面上形成一圈圈光暈。

## 3. 目前認可的設計（展覽牆 v2/v3）

### 概念對應

| 實體展覽牆 | 網站上的做法 |
|---|---|
| 大年代 | **一座城市＝一個「年代」**：大號日期（Zilla Slab）＋直式感的城市名（Noto Serif TC 900） |
| 基準線逐段升高 | 每個城市區段的 `padding-top` 依序遞減（`--s` × `--step`），轉折處畫 3px 直線 |
| 小年份刻度 | **一天＝一個刻度**：日期、星期、DAY n、地點、展品數 |
| 密排文字欄＋圖片 | 每天 N 欄，每欄寬度可個別設定，混排「文字卡／照片／短片／心得欄位」 |
| 紅色布條 | 開頭的紅色直書布條＋一張照片布條 |
| 軌道燈 | 牆頂燈軌＋`radial-gradient` 光暈（每 420px 一盞） |

### 互動（必須保留）

- **橫向捲動牆面**；滑鼠滾輪的直向捲動轉成橫向；右上角 ← → 按鈕。
- **平面圖（minimap）**：牆下方的縮圖條，依區段（序／各城市／終）分段，紅框表示目前視窗，可點擊或拖曳跳轉。
- **展品說明卡（lightbox）**：點任一影像開啟；顯示編號、標題、地點、日期時刻、媒材、說明；← → 鍵逐件瀏覽、Esc 關閉。
- **閱讀模式**：切換成直向排列（手機友善），選擇記在 `localStorage`（需 try/catch）。
- 短片在牆上**靜音循環、只在可見時播放**（IntersectionObserver）；`prefers-reduced-motion` 時不自動播放。
- 尚無內容的日子顯示虛線框「展區布置中」，城市名顯示「待補」。

### 視覺規格

- 字體：Noto Serif TC（標題）、Noto Sans TC（內文）、IBM Plex Mono（編號、時刻、檔名）、Zilla Slab（大號日期）。
- 色彩以 CSS 變數定義，**淺色與深色模式都要支援**（`prefers-color-scheme` ＋ `[data-theme]`）。淺色：牆面 `#EDEDEA`、墨色 `#1C1A18`、強調紅 `#C2332A`。
- 手機寬度（約 400px）需可用，頁面本體不可橫向溢出（橫捲只發生在牆面容器內）。

### 大阪行視覺素材（2026-10-14 加入）

- **網站標題改為「大阪行」**［事實：Viking 決定，整站標題］。標題文字改用書法圖：參考日本清酒商標的狂放筆勢，`public/art/osaka-title-v.svg`（直書，紅布條）與 `osaka-title-h.svg`（橫書，頂端列與介紹區）。SVG 以 CSS `mask` 上色，墨色跟著淺色／深色模式；`h1` 保留隱藏文字給螢幕閱讀器。
- **牆腳石垣**：`public/art/ishigaki.webp`，左右無縫重複，鋪在牆面最下方 `--dado`（桌機 150px、手機 96px）；內容區往上讓出同樣高度，石垣不壓到展品。深色模式以 `--dado-filter` 壓暗。
- **序幕天守閣**：`public/art/castle.webp`（透明背景，960×871），放大當序幕背景（桌機 620px 高、手機 440px），底部站在石垣上；紅布條與照片布條掛在它前面，介紹文字排在右側［事實：Viking 要求「放大當背景，被布條擋住也沒關係」］。
- 風格為浮世繪木版畫。來源：Viking 拍的大阪城石垣與天守照片當結構參考，本機以 FLUX.2 Klein 4B（mflux）風格化；**這些是裝飾，不是展品**，不列入展品編號。
- 素材路徑都在 `trip.yaml` 的 `art` 區塊，拿掉任一項就回到原本的文字或素牆。

### 每天的背景與序幕調整（2026-10-15 加入）

- **依 Viking 手繪草圖**：每天這一段牆有對應主題的背景。10.05 長榮客機、10.06 USJ 地球儀、10.07 勝尾寺達摩、10.08 大阪城天守、10.09 臨空城摩天輪。
- **風格**［Viking 要求「出血超過版面，才有大阪風味，什麼熱鬧加什麼，要有一點雜亂感」］：每天 6～7 張拼貼，主圖之外再疊當天的景點與招牌，大小錯落、略微旋轉，可越過當天範圍蓋到隔壁天，從牆頂鋪到石垣後面。太搶眼的部分之後靠後製與風格化統一。
- **來源**：自己的素材優先（展品照片、短片畫面、LINE 相簿裡沒上牆的新世界／道頓堀夜景與哈利波特區）。沒有的才從 Wikimedia Commons 下載：USJ 地球儀（Csiiiyu，CC BY-SA 4.0）和臨空城摩天輪（Nankou Oronain，CC BY-SA 3.0），原檔放在 `raw/art/`。CC BY-SA 要求署名，所以 `trip.yaml` 的 `sources` 會顯示在結尾；**後製過的版本也必須沿用同一授權**。
- **目前是暫用版**：只做了裁切與縮小（`public/art/days/<日期>-<序號>.webp`，`-01` 是主圖），之後會在 Mac mini 上用圖片模型後製，再替換同名檔案。位置寫在 `days/*.yaml` 的 `backdrop`：`x` 是圖片中心在當天寬度的位置（%，可超出 0～100 出血到隔壁）、`y` 是上緣在牆高的位置（%）、`h` 是高度佔牆高（%）、`r` 是旋轉角度。
- **呈現方式**：所有天的背景在牆面同一層，壓在展品後面、燈軌與屋簷石垣前面，不會蓋到隔壁天的展品（淺色模式不透明度 0.4，深色 0.3）。日期、說明與圖說加牆色光暈，背景再雜也讀得清楚。為了讓背景用整面牆高計算，年代區段與當天欄位改成撐滿牆高。閱讀模式只在每天開頭鋪主圖，最多 520px 高。
- **序幕**：照片布條換成環球影城 VIP 卡（JP-02-13），寬度和紅布條相同。石垣上方加一道瓦屋簷（`public/art/eave.svg`，SVG 手繪暫用），天守閣站在屋簷上。

## 5. 必須遵守的原則（使用者的要求或已確立的決策）

1. **說明文字只寫畫面上看得到的事實**。使用者的感受、評價、心情**不得代寫**，改用虛線「心得欄位」提示由使用者填寫。
2. **時刻不得編造**。無法從 metadata 取得就標「時刻待補」。
3. **照片順序目前是推論**（入園 → 潟湖 → 任天堂世界 → 浣熊市警察局 → 傍晚哈利波特區），使用者尚未確認；有原始檔時應以拍攝時間重排。
4. **隱私**：
   - 公開前移除所有 GPS／位置資訊（iPhone 短片的 QuickTime metadata 也有座標）。
   - 畫面中有不少**路人正臉**。若要公開，需提醒使用者篩選或替換。
   - 原始檔不進版本控制。
5. 不要再推薦一般部落格或攝影作品集主題當範本（已被否決）。
6. 每次修改後要能驗證：建置成功、隱私檢查通過、在桌機與手機寬度都看過一次。

### 後台 2.0（帳號、親友照片、留言繪馬，2026-10-17～18）

- **雙網域**：前台 `osaka2026.voriens.dev`（Worker `osaka2026`，零登入痕跡，`/api/*`、`/edit*`、`/admin*` 一律 404，只開 `/api/public/wall` 與 `/api/media/*`）；後台 `kura.osaka2026.voriens.dev`（Worker `osaka2026-kura`，完整 API＋`/edit`＋`/admin`）。兩者共用同一個 D1（`osaka2026`）與 R2（`osaka2026-uploads`）。
- **帳號**：由管理員在 `/admin` 發放（不開放註冊）；新帳號或被重設密碼都必須先改密碼，API 層也會擋。密碼 PBKDF2-SHA256 15 萬次；session 是隨機 token、D1 只存雜湊；同帳號＋IP 失敗 5 次鎖 15 分鐘；所有變更請求檢查 Origin。
- **親友照片**：`/edit` 抽屜上傳，瀏覽器先縮圖（長邊 ≤2048）抹 EXIF，伺服器再剝一次 metadata；每人每天 20 張（含已刪除）。上傳即公開，掛在指定那天最右邊的「親友照片」欄。
- **留言／繪馬**：編輯模式可直接在說明卡裡留言、回覆（也可從抽屜送）；留言掛在展品或繪馬下（說明卡裡的討論串，回覆縮排），繪馬像展品一樣掛在當天的「繪馬掛所」；每人每天 100 則。繪馬刪除後，掛在上面的留言不再公開。
- **審核**：`/admin` 的「內容審核」列出全部公開中的照片與投稿，管理員可刪除；刪除＝不再公開（照片檔一併刪除，資料列留作紀錄）。
- **公開資料不含登入帳號名稱**：牆上只顯示顯示名稱與署名。
- **測試**：改後台後在本機跑 `npm run dev:api`，再跑 `npm run test:api` 與 `npm run test:ui`（需環境變數 `KURA_ADMIN`／`KURA_ADMIN_PW`，本機管理員用 `npm run admin:create -- <帳號> --local` 建立）。

### 資料模型的關鍵決策

- **展品資訊與排版分開**：`exhibits/*.yaml` 存「這件東西是什麼」（腳本產生草稿）；`days/*.yaml` 的 `columns` 存「掛在哪一欄、欄寬多少、穿插哪些文字卡」（人工策展）。
- **城市年代不另外存**：連續且城市相同的日子自動分組；連續的 `status: pending` 日子併成一段「待補」。
- DAY n 由 `trip.yaml` 的 `start` 推算；星期由日期計算。
- 編號 `JP-<天數>-<序號>`，新素材依拍攝時間編號。
- 日期、時刻、長度在 YAML 裡**一定要加引號**，否則 Astro 的 YAML 解析器會把 `2026-10-06` 讀成 Date 物件而通過不了 schema（實測過）。

### ingest 腳本行為（已測試）

| 情境 | 結果 |
|---|---|
| 照片有 EXIF | 讀 `DateTimeOriginal` 字串取當地時刻（不做時區換算） |
| 照片無 EXIF | 時刻 `null` 並警告 |
| iPhone 短片 | 讀 `com.apple.quicktime.creationdate`（含當地時區） |
| 拍攝日期與資料夾不符 | 警告，仍匯入 |
| 已匯入過的原始檔（`source` 相同） | 略過 |
| `--redo <編號>` | 依 `crop` / `blur` / `edit`（舊格式 `clip` 仍支援）重新轉檔，只更新尺寸與長度，標題說明不動 |
| 新的一天 | 自動建立 days 檔；`pending` 的日子會轉成正式 |
| 輸出檔 | 照片與短片都不帶 metadata；`check.mjs` 用帶 GPS 的測試照片驗證過會擋下 |
| 凌晨 0:00–5:59 拍攝 | 依 30 小時制記為前一天的 24:00–29:59 |
| 展品檔有 `blur` | 轉檔時把這些區域（比例座標）擴大 35% 後模糊 |
| 展品檔有 `edit` | 短片剪輯：`stabilize`（vidstab，需 ffmpeg-full）、`smoothing`、`segments`（各段起訖秒數與 `speed`，沒列到的捨棄）、`poster`（封面秒數） |
| 結束時 | 會刪除整個 `.tmp/`（ingest 自己的暫存），不要把其他檔案放在裡面 |

**未測試**：HEIC 經 `sips` 轉檔（雲端沒有 HEIC 樣本與 sips）。第一次匯入 HEIC 時請確認結果。
